# MailHarbor integration contract

Release 0.8.0 implements the mailbox feature backlog except offline mail. Processing versions and migration behavior are unchanged.

Release 0.7.4 uses classifier version 3 with prompt/schema version 2 and action-verification version 1. Provider JSON may have an exact whole-response bare or lowercase-json code fence, removed before full validation. Correctly typed empty optional tool arrays/objects mean no operation; actual tool/permission events, nonempty or malformed tool metadata, extra prose and invalid schemas remain rejected. Relevant classifier changes selectively renew failed classification budgets and preserve cached successful results. The action-verification migration requeues only ambiguous Gmail archive checkpoints whose current reference still identifies the saved Inbox location; it preserves owners, outstanding intents, classifications and AI retry budgets.

The server web client is compatible with Thunderbird add-on 0.1.1 and connects to independently authorized IMAP mailboxes; the optional add-on keeps its own mailbox access in Thunderbird. Both clients and the optional automatic mail organizer share the same bounded Agy worker queue. Existing Thunderbird credentials are never extracted. Server-connected mailbox credentials remain in the encrypted account store and are not passed to Agy.

## HTTP API

### Unified mail web API

The session-protected `/api/mail/` routes browse the owner's connected accounts independently of Agy. They use the existing exact Host/Origin, CSRF, HttpOnly cookie, and no-store rules. POST is used for read-only listing and previews to keep private query/cursor data out of URLs.

- `GET /api/mail/folders` returns standard views (including `all`), provider folders (`folder:<opaque hash>`), built-in and custom local label folders (`tag:<id>`), sanitized errors and public account metadata. Counts are provider message totals, not account counts. Unknown filtered totals are null.
- `POST /api/mail/list` accepts `{folder,accountIds?,query?,cursor?,filters?,sort?,bodySearch?}`. Query has at most 200 characters. Filters: `from,to,subject,body,since,before,unread,starred,hasAttachment,minSize,maxSize`; dates are inclusive since/exclusive before. Sorting: `date_desc,date_asc,subject_asc,sender_asc`. It returns `{folder,messages,nextCursor,errors,total,totalComplete}` with up to 50 rows and opaque references. Rows may include CC, Reply-To, reference headers, thread ID, size and attachment presence. Pagination binds all search options, account revisions and provider snapshots.
- `POST /api/mail/message {id}` returns a bounded quick text preview and verified attachment metadata. Opening does not mark Seen. `POST /api/mail/content {id}` parses the full source, returning plain text, sanitized HTML with safe raster CID images, address details and encryption metadata. Limits: 160 MiB raw source, 8 MiB combined rendered text/HTML. All provider reads use PEEK and identity checks.
- `POST /api/mail/decrypt {id,privateKey,passphrase?,certificate?}` handles OpenPGP/PGP-MIME and RSA S/MIME EnvelopedData. Credentials are used only for this request; signatures are explicitly unverified. Decrypted attachment bytes are delivered to the current browser response only.
- `POST /api/mail/source {id}` exports EML; `/headers {id}` exports raw headers. `/attachment {id,attachmentId}` downloads at most 100 MiB decoded; `/attachments {id}` downloads a ZIP of all attachments with a 100 MiB aggregate bound. `/attachment-preview {id,attachmentId}` produces bounded DOCX/XLSX/PPTX text previews (25 MiB input, 32 MiB XML, 1,000 entries). Binary downloads use no-store, nosniff, sandbox CSP, application/octet-stream and sanitized attachment filenames.
- `POST /api/mail/action` accepts `{id,action,destinationId?,confirm?}`. Actions: `mark_read,mark_unread,star,unstar,delete,archive,move,restore,spam,not_spam,delete_permanent`. Flags and native MOVE affect verified provider identities. Gmail archive removes Inbox membership. Permanent deletion requires explicit `confirm:true`, verified Trash and UIDPLUS exact UID expunging; no blanket EXPUNGE fallback. Success returns `{applied:true,undoToken?}`; Undo is available only when provider mapping confirms the new identity. `/undo {token}` moves it to the verified source within 15 minutes.
- `POST /api/mail/bulk {ids,action,destinationId?,confirm?,tag?,enabled?}` processes 1–50 distinct listed IDs and returns separate applied/failed IDs and undo tokens. `action:"tag"` changes local labels. `/trash/empty {accountId,confirm:true}` snapshots and permanently deletes up to 100 verified Trash messages, returning deleted/remaining counts and partial errors while preserving new arrivals.
- `POST /api/mail/tags {id,tag,enabled}` changes only encrypted local labels and returns updated tags and label counts. `/labels/manage` accepts create `{action,label}`, rename `{action,id,label}` or delete `{action,id}` for custom labels. Up to 100 custom definitions; built-in definitions cannot be changed. `/folders/manage {accountId,action,name,folderId?,parentId?}` creates/renames permitted provider folders. `/provider-labels {id}` lists available Gmail labels or IMAP keywords; `/provider-labels/apply {id,label,enabled}` edits them when supported.
- `GET /api/mail/smtp` returns public outgoing settings and reconnect requirements. POST saves permitted TLS port, Sent-copy preference and optionally a separate password in encrypted storage; SMTP destinations remain bound to the connected provider. `/smtp/test {accountId}` verifies without sending. `/compose/context {id,mode}` prepares reply/reply_all/forward/edit using verified source and connected sender identity.
- `POST /api/mail/draft` and `/send` accept `{accountId,draftId?,to,cc,bcc,subject,text,attachments,inReplyTo?,references?,requestId?}`. Attachments are `{filename,mimeType,content:base64}` with 25 MiB aggregate decoded bytes, maximum 50 files; up to 100 recipients and 200,000 body characters. HTTP JSON is capped at 36 MiB. Send requires a stable request ID and records single-attempt state durably before SMTP. Ambiguous outcomes cannot automatically resend; partial acceptance and Sent-copy/draft-cleanup failures are explicit. Draft replacement requires exact old identity and UIDPLUS; lost APPEND acknowledgement is treated as uncertain.
- `GET /api/mail/updates` activates short-lived Inbox STATUS watching and returns a revision. The server checks every 60 seconds while a view is watched or a push device exists. `GET /api/mail/notifications` returns the public VAPID key; POST saves a validated browser push subscription (up to 16), DELETE removes `{endpoint}`. Encrypted subscriptions only accept supported push-service HTTPS endpoints. Generic alerts contain no sender, subject or mail body. Browser display requires explicit opt-in and platform permission.
- `GET /api/mail/calendar?id=…` exports a verified cached appointment as sanitized ICS; it never sends invitations or creates a provider event.

Labels use the encrypted-per-record SQLite mail index for full mailbox scale. The legacy optional `mailTags` field in the encrypted account store retains schema 1 and its 10,000-entry bound for compatibility; existing entries are imported once as manual labels. SQLite entries use a hash of account ID, normalized mailbox email and immutable message fingerprint and retain manual, automatic and excluded labels, bounded public headers, a private IMAP reference and update timestamp. They never contain message bodies. Manual exclusions prevent automatic labels reappearing in label views, but do not erase cached classification evidence used by retention. Matching source observations refresh existing entries; they never create labels. Same-mailbox reconnection preserves labels, while a different mailbox identity cannot access them. Label pagination binds a monotonically increasing index version so changes require Refresh rather than silently shifting page boundaries. Saved headers may be stale after external changes; preview/actions revalidate the original reference and fail safely until a moved message is rediscovered. Label removal is local and remains possible after preview failure.

Mailbox references and cursor contents stay on the server; clients cannot supply provider UIDs or paths for operations. Pagination tokens bind folder, query, account selection, revisions, folder UIDVALIDITY and arrival bounds. They expire after 15 minutes or a service restart. The browsing cache is bounded to 5,000 header references, 100 cursors and four concurrent API operations; these limits do not cap the separate durable processing index. Independent account reads run concurrently, with sequential commands inside each connection and no nested FETCH commands. Account disconnect aborts affected in-flight browsing. Errors preserve healthy account results without reflecting provider diagnostics. The browser clears mail on session loss and never stores it in its offline cache.

Manual deletion keeps an encrypted label-suppression marker for the same account identity and message fingerprint. This prevents delayed or rescheduled organizer classifications from recreating labels for deleted mail, including mail that had not been classified yet. Explicitly labeling that message again clears suppression. Attachment downloads decode only MIME transfer encoding and preserve original charset/flowed bytes; 64 KiB source reads are bounded by a 75 MiB plus 64 KiB encoded limit, and an incomplete part is never returned as a complete download.

### Automatic mail organization

See [PROCESSING.md](docs/PROCESSING.md) for all thirteen policies, calendar arithmetic, provider behavior, model input limits, resumable storage and invoice queue integration. The owner must explicitly permit bounded text from all folders, including Junk, to be sent to Gemini before processing starts. The model proposes classifications and dates; deterministic server policy alone chooses actions. It cannot choose provider commands or destinations.

- `GET /api/mail/processing/status` returns enabled/running phase; `workerState` (`running`, `paused`, `retrying`, `blocked`, `idle`, `stalled`); progress and actual scheduled retry time; analysis coverage, blocker counts, connected-account discovery/cooldowns, safe diagnostics, batch metrics, migration, policies and preview. Disabled processing exposes no next attempt. Coverage counts indexed logical messages; hold/review categories may overlap analyzed mail and must not be added to cumulative provider-action counts.
- `POST /api/mail/processing/settings` accepts `providerConsent`, constrained tender grace fields, optional `maxActions` (0–1000) and `maxClassifications` (1–1000); null removes a cap. Settings cannot change during active work or an owner edit. Caps and consumed counts persist across runs and restarts for the configured pilot; explicitly configuring a limit starts its new budget. Move/rescue attempts are reserved in the durable intent transaction before issuance, so unknown outcomes consume `maxActions`. Read flags/local labels are not capped. `maxClassifications` caps saved successes, not failed calls or synthetic probes. Use preview for zero provider writes.
- `POST /api/mail/processing` accepts `{action:"start"|"pause"|"preview"}` and returns HTTP 202 with status. Start and preview continue in the background. A preview may classify a small sample and cache its result but makes no provider changes, labels or Drive filings.
- `GET /api/mail/processing/review` accepts `category=review|held|failed|retry` and optional opaque `after`, returning up to 50 records with reasons and a next cursor. `GET /api/mail/processing/review/message?id=…` returns a revalidated bounded plain-text preview.
- `POST /api/mail/processing/review` accepts `{id,action:"retry"|"keep"|"confirm",labels?,dates?}`. Retry resets bounded attempt state; Keep persists a retention hold. Confirm requires complete verified content, validates dates and preserves previous protective categories. Owner writes exclude concurrent processing/review writers and do not undo an intervening Pause.

Apply mode handles bounded cached-read and discovery budgets before interleaving further discovery, due retention and classification. Headers are saved before each verified read batch and the folder checkpoint advances afterward. UIDVALIDITY, the after-UID checkpoint and a frozen upper UID watermark survive restarts; unfinished scans resume that bound and later arrivals enter a subsequent pass. During a backlog, arrival discovery/read flags recur every fifteen minutes between classification operations. Connected accounts rotate, with opportunities reserved for old mail, newer arrivals and due recovery. Preview makes no flag changes.

Completed classifications are cached by logical-message fingerprint before labels or moves, and future retention checks reuse them. Failed or interrupted provider calls may still require retry. The processor moves expired deletable categories to provider Trash, archives retained categories and rescues Junk when complete content receives Gemini's legitimate verdict with confidence at least 0.98, including mail from new senders. It never expunges mail. Trash recovery depends on the provider's own automatic cleanup. Overlap preserves the longest period and chooses Archive if any applicable rule archives; incomplete or uncertain evidence and unresolved invoice records hold moves. Tender archiving uses an explicitly configured grace period after a confirmed deadline, or six calendar months after receipt when no deadline can be established. An unconfigured grace holds dated tenders while other rules can operate. A run with folder or message-read failures reports `lastRun.status:"partial"`; it must not be presented as full completion, and saved progress supports future retries.

Gmail Archive removes Inbox membership while preserving All Mail and other labels. Sent messages retain Gmail's immutable Sent label and already count as archived when outside Inbox. Only an explicit Gmail provider identity and matching physical `emailId` allow aliases to share one move. Every alias role contributes its retention or hold, preserving the longer rule. Successful `applied`/`already_target` results checkpoint all matching aliases; an absent source leaves remaining aliases eligible for later revalidation. Distinct Gmail IDs and non-Gmail copies remain separate targets. Other providers require a verified existing archive folder and native MOVE. Missing destinations and stale identities leave mail in place. Calendar downloads remain explicit user actions.

The SQLite index stores encrypted metadata payloads, HMAC-derived label/account lookup tokens, and indexed scheduling state/due times. It contains no mail bodies or attachment archive. Existing invoice parsing continues locally; classifier-discovered historical invoices enter the encrypted durable invoice queue and the existing Drive filing workflow. The single Agy worker is shared with briefings, without paid-overage fallback or model substitution.

Runtime classification starts at 12 messages per batch; the protocol ceiling remains 40 messages, 512 KiB per request and 8,000 body characters per message. Version 0.7.0 uses classifier/prompt/schema version 2 with shared field/date/length constraints. Provider-only short IDs and sparse dates are restored before strict validation. Only explicit-zone minute timestamps and valid numeric confidence when no dates exist receive harmless canonicalization. Successful version-1 results remain cached. Batch size decreases on failures/timeouts and grows after three valid batches taking under sixty seconds, never above 12. A worker timeout normally schedules sixty seconds; a message's own later deadline still applies. Quota uses the actual persisted shared cooldown, including seven days for weekly exhaustion. The scheduler honors the remaining deadline rather than replacing it with the normal fifteen-minute pass interval.

An invalid model batch accepts no partial classifications and retries at a smaller size. Isolated invalid replies, timeouts and provider errors have a durable three-failure budget, with fifteen- and thirty-minute eligibility delays before exhaustion becomes a technical failure. Splitting batches and interrupted requests can cause additional calls. Three consecutive isolated failures open a circuit breaker: one synthetic probe after cooldown checks recovery without consuming backlog mail. Failed probes back off up to four hours; valid mailbox results reset the streak. Login/configuration failures block until corrected. Temporary read-flag/move failures retain intents and retry deadlines; account TLS failures and timeouts receive exponential backoff with jitter. Unverified read flags prevent moves. Diagnostics contain only allowlisted stage/reason pairs, phase, account identity and protocol/TLS codes, never raw replies or mail content.

Transient body-read `mailbox_error`/`mailbox_timeout` failures retry after at least fifteen minutes; three failures leave a technical failure with no automatic deadline. Stale references fail immediately. Explicit retries and migration of incomplete results may reread previously classified mail while retaining old protective evidence. Processing extraction version 2 may expand a source-limited inline prefix once from 64 KiB to 256 KiB; final AI text remains at most 8,000 characters, MIME headers at most 16 KiB, with attachments/encryption excluded. Browsing retains its ordinary source limit.

The additive processing migration commits pages and its cursor together, preserves successful classifications/owner pause/move journals, and selectively requeues old failures and incomplete-content recovery. A renewable per-instance SQLite lease covers initialization, migration, runs and owner mutations. Failed durable writes or corrupted encrypted records block subsequent processor effects. Back up the SQLite state and matching key together; a rollback to older code must remain paused until new owner/retry metadata is shown compatible. Restoring database state cannot undo provider-side mail changes. Live pilot, throughput and twenty-four-hour observations are deployment acceptance evidence, not guarantees implied by this API.

### Briefing API

All requests require `Authorization: Bearer <pairing token>`. All JSON responses have `Cache-Control: no-store`. No request/response bodies or tokens are logged. No permissive CORS. Client fetches use `redirect: error`.

- `GET /v1/status` -> `{version:"0.7.4", model:"gemini-3.8-flash-high", ready:boolean, detail:string, code, retryAt?, retryAfterMs?}`. This checks local readiness and durable cooldown only, never contacts Google.
- `POST /v1/jobs` -> HTTP 202 `{id, status:"queued"}`. Body is `{language:"en", messages:[...]}`. Language is an optional short language tag, default en. Message fields: `{id, account, author, subject, date, body, truncated, bodyUnavailable}`. IDs are opaque batch-specific strings, never Thunderbird message IDs. Other string fields are supplied by the add-on. Booleans are required. Maximum 40 messages, 8000 body characters per message, 512 KiB request; subject/author/account max 500, date max 80, id max 100. Server rejects unknown fields, duplicates, invalid types and excessive lengths.
- `GET /v1/jobs/<id>` -> `{id,status:"queued"|"running"|"completed"|"failed"|"cancelled", result?, error?, metrics?}`. Completed/failed job metrics contain `batchSize`, `latencyMs` and `queueWaitMs`; classification jobs add `classifierVersion` and `schemaVersion`. When CLI initialization was validated, optional `startupMs` measures spawn-to-validation and `responseMs` measures initialization-to-terminal-response/stop. These are bounded numeric fields supplied by an internal observer, never public request parameters or raw provider output.
- `DELETE /v1/jobs/<id>` cancels pending or active job -> `{id,status:"cancelled"}`. Do not include input message bodies in job responses.
- Errors: `{error:{code,message,diagnostic?,retryAt?,retryAfterMs?}}`. Diagnostic is a fixed allowlisted `{stage,reason}` pair. Quota errors carry the durable ISO deadline and bounded remaining milliseconds, including queued failures and submissions after restart. Machine codes include unauthorized, invalid_request, busy, login_required, quota_exhausted, timeout, invalid_model_output, provider_error, configuration_error, not_found.

Result: `{briefing:string, items:[{id, summary, priority, category, recommendation, reason}]}`. Every input ID must occur exactly once; no additional IDs. `priority`: high|normal|low. `category`: action|waiting|invoice|newsletter|notification|other. `recommendation`: keep|archive. Briefing <=12000 chars, summary <=1200, reason <=500. No executable output, arbitrary actions, HTML, URLs or Thunderbird IDs. Incomplete/encrypted/unavailable messages must be kept. Archiving is a suggestion, not permission.

Server limits: 1 running Agy process, 5 queued jobs, 120 second worker timeout by default, in-memory job retention <=15 minutes. Cancel/timeout terminates process tree. Rate/quota failures halt retries and expose a clear state. Each batch uses a fresh conversation and isolated scratch directory; email text enters via stdin, not a shell string or argv.

## Add-on

Thunderbird standard MailExtension (target supported current ESR, prefer >=140 if APIs permit). Toolbar opens/reuses dashboard. Setup: server HTTPS origin, pairing token, account selection and disclosure that selected email text is relayed to Google through Agy. Request only the chosen origin through optional host permissions; no unconditional all-host grant. Endpoint origin has no path/query/credentials. Save token locally and do not render it after save.

Scan unread headers from selected real inboxes (not virtual folders/All Mail), paginate with cancellation, and retain only the newest 40 plus a cap sentinel. Read only the selected bodies, cap 40 visibly, extract plain inline content without attachments/decryption, preserve unread status. Show full dates including the year. Opaque IDs and fingerprints are session-scoped. Results and actions stay in memory. Revalidate message fingerprint/account/inbox before manual archive or mark-read; stale proposals cannot mutate mail. Use native `messages.archive` to respect configured archive destinations. No permanent deletion. Review UI uses textContent and defaults to no selections. Reading/listening does not mark read. Expose explicit archive and mark-read controls.

Speech: feature-detected OS voices in dashboard, Play briefing / Read email / Pause / Resume / Stop and speed/voice selection. If unavailable, show clear fallback guidance, never pretend audio played. Voice implementation must not require paid Gemini TTS API.

## Web client and server mailboxes

Static app resources are available at `/`. The authenticated JSON web API lives at `/api/`; legacy `/v1/` remains bearer-only and cannot access web-owned jobs. Browser sessions use a HttpOnly, Secure, SameSite=Lax cookie. Mutations require the exact configured Origin and a session CSRF token. Host is matched exactly; no wildcard CORS is provided. Only an explicitly allowed Tailscale Serve user identity or a valid pairing token can create a browser session. All valid sessions belong to one owner and may resume that owner's briefing during its in-memory retention window.

Tailscale identity sign-in intentionally trusts the loopback proxy boundary: it accepts an allowed `Tailscale-User-Login` header only from a loopback connection at the configured HTTPS origin. It does not cryptographically distinguish Serve from another local process that can supply that header. This deployment therefore trusts local host users and services, including any other process running under the service account.

- `POST /api/session` with `{token}` or `{tailscale:true}` signs in; `GET` returns `{authenticated,csrf,version}`; `DELETE` signs out that device.
- `GET /api/status` returns shared Agy readiness. `GET /api/accounts` returns public account and provider-registration metadata plus `oauthFailure` (null or `{provider,code,message}`), never stored passwords/secrets/tokens. OAuth failure messages are fixed local text distinguishing token exchange and IMAP verification failures; diagnostics belong only to the current browser session and clear on a new authorization attempt or success. Provider response bodies and descriptions are never exposed.
- `GET /api/agy/login` reads the current browser session's reconnect state without contacting Google. `POST` with `{}` explicitly starts Agy login; `POST /api/agy/login/code` accepts only `{code}`; `DELETE /api/agy/login` with no body cancels it. Mutations require the normal Origin/CSRF checks; query parameters are rejected. One active attempt is bound to its initiating session and expires after ten minutes. Responses contain a sanitized state, optional expiry/error, and a validated Google authorization URL only while awaiting the code. Logout and session expiry cancel the owned attempt. Verified login clears only the queue's authentication pause; failed jobs are not replayed, and quota/configuration failures remain blocked.
- `POST /api/providers` saves an owned Google/Microsoft OAuth client registration. `POST /api/accounts/password` validates the added account's password or app password, with an optional separate SMTP password. Microsoft presets use OAuth only. `POST /api/accounts/oauth` begins PKCE authorization; `/oauth/google/callback` and `/oauth/microsoft/callback` finish a one-use, session-bound state exchange and verify IMAP access.
- `POST /api/accounts` creates a disconnected account from `{provider,email,label?,username?,incoming?,smtp?,allowLocalBridge?,tlsCertificate?}`. Provider catalog IDs and generic help are returned by the accounts API; repeated provider types are allowed. Account identities, passwords and OAuth connections are separate.
- `POST /api/accounts/:id/test` verifies login and lists folders. `POST /api/accounts/:id/archive` selects an existing safe archive folder. `DELETE /api/accounts/:id` removes this server connection and invalidates its reviews; it does not delete the mailbox.
- `POST /api/briefings` with `{accountIds,language}` starts a server scan. `GET /api/briefings` lists resumable batches; `GET /api/briefings/:id` includes bounded extracted source messages and validated results. `DELETE` explicitly cancels/erases that batch.
- `POST /api/briefings/:id/actions` with `{action:"archive"|"mark_read",ids:[...]}` returns per-message applied/failed outcomes. The server rechecks account revision, UIDVALIDITY, UID, envelope fingerprint, unread status and inbox membership. IDs and references originate only from the scan; model output never authorizes a mutation.

Accounts are user-created from generic provider presets or custom IMAP/SMTP settings. No account identity or credential is preconfigured. Remote endpoints require TLS/STARTTLS and certificate validation; local Proton Bridge requires explicit loopback opt-in and an exported trust certificate. Search each real inbox for unread UIDs, then use progressively wider sent/received date searches for large inboxes. Fetch each matching header at most once, intersect results with the original UID snapshot, finish each window before evaluating its date bound, and retain the globally newest 40 plus a sentinel. Small inboxes and exhausted date windows use full header enumeration. A five-day margin conservatively handles numeric time-zone offsets; ImapFlow may use WITHIN for received-date searches, so normal provider/server clock synchronization is assumed. Malformed Date headers can be interpreted differently by the provider and JavaScript; ordering is not guaranteed across that parser disagreement. The 120-second session deadline remains enforced and reports `mailbox_timeout` distinctly.

Fetch selected metadata in batches, then group messages choosing the same inline text MIME section. Request only that section with PEEK/read-only mailbox selection and recheck identity and unread flags on each returned message. Each message has a 64 KiB encoded text-prefix ceiling, a 16 KiB MIME-header ceiling, a 64 KiB decoded ceiling, and an 8,000-character final text ceiling. Reaching a body limit marks the text truncated; reaching the MIME-header limit makes its body unavailable. An encoded prefix can produce less decoded text than the previous streaming reader. Exclude attachments and encrypted content, preserve supported transfer/charset and flowed-text decoding, and cap HTML conversion. Never issue another IMAP command inside a FETCH iterator. Gmail archiving removes only the Inbox label; other mailboxes require a verified archive destination and native MOVE, never an EXPUNGE fallback. Missing/changed mail is rejected or skipped safely. Partial action results are explicit.

Web scans continue across browser suspension; no unload/pagehide handler cancels server work. Batches expire within 15 minutes and are not persisted across restarts. Static service-worker caching must never cache APIs, OAuth callbacks, source mail, credentials, or personalized responses. Audio is user-started device speech; a better voice is outside this version. Opt-in background Web Push is described above.

## Deployment

Native Node.js >=22 service on Linux under a non-root account. Use a dedicated service account or VM for isolation from unrelated host data; the separate Agy profile alone is not an operating-system security boundary. Bind only 127.0.0.1:8765; Tailscale Serve provides tailnet-only HTTPS. Browser/app Agy reconnect uses the CLI's remote OAuth flow under the worker account, with `/usr/bin/python3` and the private `scripts/agy-login-pty.py` helper; `scripts/login.mjs` remains the interactive fallback. No extracted OAuth tokens or API key fallback. Agy requires an unlocked, accessible Linux Secret Service/D-Bus keyring, and this must be tested after restart. Opening Settings/status makes no provider call; explicit reconnect sends no email content or AI prompt. Dedicated Agy profile denies tool read/write/commands/network browsing/MCP and excludes plugins/global instructions. Treat email as untrusted content. Native profile configuration and runtime checks are fail-closed. Baseline Ultra quota is distinct from credit overages; no automatic paid overages or model substitution.
